# 仅数据库读取与回复生成

本模式使用普通微信客户端、已有数据库密钥和本机数据库读取服务。回复模式固定为“仅生成，不发送”，生成的内容保存在概览的“最近记录”中，不进入微信发送接口。历史已生成记录不会自动补发。

## 配置步骤

1. 在连接设置中选择本机普通微信程序的位置（可留空并自行打开微信），打开微信并登录目标账号，等待数据库同步。
2. 自动查找账号目录，或选择包含 `db_storage` 的账号目录，确认当前账号。
3. 已保存的有效密钥可直接复用；没有可用缓存时，手动填写该账号已有的有效数据库密钥，再连接并验证。控制台不提供自动提取密钥、Hook 构建、部署或修复入口。
4. 连接 DSH，启动服务，配置允许的聊天。生成结果在“最近记录”查看。

“打开微信”仅启动普通微信程序。程序路径保存在 `runtime.wechatExecutable`；`runtime.sender` 为 `database-only`。遗留 `config.hook` 字段不参与此模式。所有读取配置保存请求均发送 `autoKey: false`。

## 登录账号核对

账号核对通过系统文件占用信息检查微信当前使用的数据库，并与所选账号目录比较。仅发现微信进程不能证明已经登录。未登录、账号不一致、多个客户端或多个账号数据库、核对失败或超时都会阻止继续；原配置保留。检测到程序目录存在 version.dll、无法确认无 Hook 时，应完整退出客户端并使用未加载 Hook 的普通微信。

本模式不注入微信、不自动抓取密钥、不发送回复，但不保证零风控风险。数据库格式、密钥有效性、客户端同步状态及系统文件占用查询权限仍可能影响可用性。

## 验证边界

自动化测试使用页面函数、临时配置及替代依赖，不启动真实微信、不获取真实密钥、不发送真实消息。运行 `node --test scripts/test-no-hook-ui.mjs` 可检查控制台入口与密钥保存请求约束。

## 启动与保存位置

启动顺序为：准备配置（旧 Hook 配置备份到 `state/migrations/no-hook-v1`）→ 启动数据库读取服务 → 同步读取账号 → 系统文件占用校验 → 检查 DSH → 启动消息桥接与仅生成适配器。生成前与运行中继续校验账号，失败时不放行。该路径没有 Hook 启动步骤，也不访问原生发送端口。

生成正文保存在 `state/accounts/<账号标识>/reply-previews.jsonl`；没有账号作用域的旧记录保存在 `state/reply-previews.jsonl`。控制台概览“最近记录”可查看完整正文。历史已发送或发送状态不明的操作保留原状态，不会重新标记成未发送。

系统校验检查所选账号及同一父目录下的其他账号数据库。系统未报告占用、目录联接、权限错误、过期快照和进程身份变化均拒绝通过，不会回退到 Hook。此方式可能因系统未提供足够证据而拒绝已登录客户端；没有真实登录客户端时，自动化测试不能证明实际账号校验成功。

仓库保留原 Hook 原生源码供来源审计；构建、部署、配置和原生调用入口均已禁用，发行包不包含这些原生源码或注入/抓密钥 DLL。旧安装中未处于微信加载目录的文件保留，不会自动删除未知 DLL；带相邻 `version.dll` 的客户端启动会被拒绝。
