# 无 Hook、仅用已有密钥生成 实施计划

> 按 superpowers:subagent-driven-development 分工实现；每项先验证失败场景，完成后复核需求与代码质量。

**目标：** 保留数据库读取、模型生成和未发送记录，禁用所有 Hook 入口及微信自动发送；以非注入系统校验替换登录和启动校验。
**架构：** Windows 独立进程通过 Restart Manager 查询账号数据库的使用进程；业务层将进程、账号和异常快照映射为严格的校验结果；界面仅提供已有密钥验证与本地生成。未知/多账号/不可确认均拒绝通过。

- [x] 系统探测：查询已选账号及相邻账号的数据库文件使用者，关联微信进程树及进程创建时间；不注入、不读内存、不调用发送 Hook。
- [x] 校验与运行：连接前后及启动/运行时复用校验，读取服务返回的目录必须与配置一致；无法校验不放行。
- [x] 禁用入口：抓密钥代码删除/阻断，native HTTP 永不调用，发送始终本机预览；旧 build/configure Hook 入口禁用，打开微信改普通启动。
- [x] 界面与打包：仅生成模式锁定；只验证已有密钥；不再部署/要求发送与抓密钥 DLL。
- [x] 回归：进程不存在、登录未完成、错账号、多账号、权限失败、PID变化、有效读取、零 Hook/发送；使用合成文件锁验证系统探测。
- [x] 部署：备份代码/配置；迁移无Hook配置；检查旧客户端中项目 version.dll，符合已知哈希且未运行时隔离备份；不删除未知DLL，不关闭用户微信。


实施结果：全局仅生成、禁用自动抓密钥与全部 native HTTP；旧 Hook 构建/配置/客户端修改/健康检查入口拒绝。安装副本已备份并更新；普通客户端 D:/Weixin/Weixin.exe 已验证腾讯签名且没有相邻 version.dll。旧项目匹配客户端和 DLL 留在原目录归档，未启动、未移动、未更改 ACL；新配置不再引用。

部署后通过本机控制台 API 确认 database-only/preview，新账号检查在微信未运行时返回 WECHAT_NOT_RUNNING。未启动真实微信、未抓密钥、未发微信消息；真实登录后的账号占用与模型生成仍需在用户登录后验证。安装包构建未执行，当前机器缺少所需完整构建环境。
